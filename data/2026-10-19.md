Motivation: 推理是ReAct类编程智能体的核心，但目前不清楚智能体是否以及如何对代码进行推理；同时观察到推理虽有益却基本处于无引导状态（定位停留在表层症状、无法精修接近正确的补丁、忽略issue需求、生成的测试行为多样性不足）。

Method: 实证部分：从6个单/多智能体脚手架、4种编程语言、SWE-bench-Verified/Pro/Lite上收集7,955条轨迹，归纳出12种代码推理形式并分析其与解决率、任务复杂度的关系，同时归类四类推理缺陷。方法部分：提出DeskCheck脚手架，按阶段系统引导推理——模拟执行路径定位根因、模拟候选补丁以精修near-miss、按issue需求审计补丁、在生成测试前推理边界输入与期望输出。

Result: 66.95%的轨迹中包含代码推理，其与更高解决率相关且强度随任务复杂度上升。在731个SWE-bench-Pro实例上，DeskCheck较mini-SWE-Agent与Claude Code提升解决率6.29%–10.53%，额外成本$0.02–$0.28/实例（均值$0.14）。分阶段分析显示方法级定位召回更高、对定位不精确issue的修复更成功、对near-correct补丁遗漏边界情况的检测更好；McNemar检验在所有被测LLM上均显著（p<10^-10），重复实验验证了对智能体非确定性的鲁棒性。

Conclusion: 代码推理是编程智能体性能的重要抓手，但当前智能体对推理的利用是无引导、不充分的；通过脚手架系统化地组织各阶段的代码推理，可在较低成本下稳定、显著地提升仓库级issue解决能力，支持"系统化代码推理"作为改进编程智能体的有效途径。

Abstract: Reasoning is central to ReAct-based programming agents, yet whether and how they reason about code remains unclear. We study 7,955 issue-resolution trajectories from six single- and multi-agent scaffolds across four programming languages on SWE-bench-Verified, SWE-bench-Pro, and SWE-bench-Lite. We identify 12 forms of code reasoning in 66.95% of trajectories. Code reasoning is associated with higher resolution rates, and its intensity increases with task complexity. However, it remains largely unguided: agents may focus on surface-level symptoms during localization, fail to refine near-correct patches, overlook issue requirements, and generate tests with limited behavioral diversity. To address these limitations, we propose DeskCheck, an agentic scaffold that systematically guides code reasoning throughout repository-level issue resolution. DeskCheck simulates execution paths to localize root causes, simulates candidate patches to refine near-misses, audits patches against issue requirements, and reasons about corner-case inputs and expected outputs before generating tests. On 731 SWE-bench-Pro instances, DeskCheck improves resolution rates over mini-SWE-Agent and Claude Code by 6.29% to 10.53%, at an additional cost of $0.02-$0.28 per instance (average: $0.14). Per-phase analyses show higher method-level localization recall, more successful repairs of imprecisely localized issues, and better detection of missed corner cases in near-correct patches. Exact McNemar tests show statistically significant improvements across all subject LLMs (p < 10^-10), while repeated experiments support robustness to agent nondeterminism. These findings motivate systematic code reasoning as a means of improving programming agents.
